# 프롬프트 코치

수업용 도구. 코딩 AI에게 줄 **첫 프롬프트**를 빠짐없이 만들고, 결과가 어색할 때 **"어디가 · 무엇이 · 어떻게"** 를 물어 **고치는 프롬프트**로 바꿔 줍니다. 서버 없이 브라우저에서만 돌아가고(PC·모바일, 홈 화면에 추가하면 앱처럼), 모든 내용은 기기에 저장되며 과제 제출은 JSON 내보내기로 합니다.

## 왜 이런 구조인가

AI가 좋은 결과를 못 내는 이유는 거의 둘 중 하나입니다. ① 결정을 안 해 줘서 AI가 멋대로 정함, ② 틀린 걸 틀렸다고 말해 주지 못함. 도구는 이 둘을 각각 맡는 두 모듈로 나뉘고, 둘 다 같은 "결정 목록"을 공유합니다.

| 구역 | 하는 일 |
|---|---|
| **결정** | 템플릿의 결정 항목마다 `내가 정함 / AI에게 / 모름`. "아직 말하지 않은 것"이 눈에 보이고, 모르는 항목은 프롬프트가 "AI가 2안을 내고 물어보게" 요청합니다. 선택마다 **검수 기준**이 자동으로 붙습니다. |
| **참고** | 참고 이미지를 여러 장, **역할**(구도 / 그림체 / 특정 오브젝트 / 색감 / 하지 말 것)과 메모를 달아 둡니다. 프롬프트에 번호와 역할이 적힙니다. |
| **첫 프롬프트** | 영어(AI 입력용)와 한국어(같은 뜻)를 나란히. 복사 · TXT 저장. 결과를 본 뒤 마음에 드는 것은 **잠금**에 적어 두면 이후 모든 프롬프트에 "바꾸지 마"로 붙습니다. |
| **코치** | 결과 스크린샷에 영역을 표시 → 그 자리의 것 → 문제 갈래(형태 / 색 / 빛 / 재질 / 배치 / 움직임 / 구도 / 성능) → 구체적 증상 → 참고와 가장 다른 점 → **수정 프롬프트**. 증상마다 "왜 이런 일이 생기나"가 붙어 그 자리에서 배웁니다. "플라스틱 같아요" 같은 말로 찾는 **느낌 사전**도 있습니다. |
| **기록** | 반복마다 프롬프트·스크린샷·별점·해결 여부. 쌓이면 자주 틀리는 패턴을 보여 줍니다. |
| **설정** | 프로젝트 JSON 내보내기(제출)·삭제. 시작 화면에서 JSON 불러오기. |

## 템플릿 갈아 끼우기

템플릿은 `public/templates/*.json` 하나로 과제 하나입니다. 코드를 건드리지 않고 추가합니다.

1. `public/templates/<id>.json`을 만듭니다. 구조는 `src/types.ts`의 `Template`을 따르고, `miniature-island.json`이 전체 예, `product-shot.json`이 작은 예입니다.
2. `public/templates/index.json`에 `{ "id", "name", "description", "file" }` 한 줄을 추가합니다.

템플릿 한 개에 들어가는 것:

- `decisions` — 결정 항목. `kind`는 `choice`(하나) / `multi`(여러 개) / `text`(자유 입력). 선택지마다 `text`(영/한 프롬프트 문장)와 선택 시 추가될 `checklist`. `importance: "core"`는 "핵심" 표시, `"nice"`인 자유 입력은 비워 둬도 미결정으로 세지 않습니다.
- `sections` — 프롬프트 순서. 각 섹션은 결정 id 목록이거나 `auto`(참고 이미지 / 미결정 항목 / 검수 기준 / 잠금 / 작업 방식).
- `checklistBase`, `process` — 항상 붙는 검수 기준과 작업 방식.
- `diagnosis` — 진단 트리. 갈래(category) → 증상(symptom). 증상마다 `label`/`labelEn`, `fix`(수정 요청 문장, `{target}`에 가리킨 것이 들어감), `why`(교육용 설명), `examples`(전후 사진, `public/` 아래 경로).
- `compareAxes` — 참고 이미지와 비교하는 축.
- `feelDictionary` — 일반인의 말 → 증상 id → 기술 용어.
- `targets` — "그 자리에 있는 것" 선택지 (`ko`/`en`).

템플릿 파일이 잘못되면(중복 id, 없는 증상 참조 등) 앱 상단에 어디가 틀렸는지 표시됩니다.

## 개발

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # dist/
```

Vite + React + TypeScript, 의존성은 React와 PWA 플러그인뿐. 상태는 IndexedDB(`src/lib/db.ts`), 프롬프트 조립은 `src/lib/assemble.ts`, 화면은 `src/components/`. `main`에 푸시하면 GitHub Actions가 GitHub Pages로 배포합니다(`.github/workflows/pages.yml`; 저장소 설정 → Pages → Source를 "GitHub Actions"로).

## 수업에서 쓰는 순서

1. 템플릿 고르고 결정 내리기 → 참고 이미지 달기 → 첫 프롬프트 복사 → 코딩 AI에 붙여넣고 이미지를 같은 순서로 첨부.
2. 결과가 오면 마음에 드는 것부터 **잠금**에 적기.
3. 어색한 곳마다 **코치**로 한 번에 하나씩 수정 프롬프트 만들기 → 결과가 오면 별점.
4. 끝나면 **설정 → JSON 내보내기**로 제출. 기록의 "패턴"이 그 학생의 다음 수업 내용입니다.
