# 프롬프트 코치

2D Image·3D Web·Video 장면을 위한 요청문을 만들고 다듬는 도구예요. 원하는 장면을 자유롭게 적고, **왜 그 조건이 필요한지** 예시로 배우면서 첫 프롬프트를 구성합니다. 기존의 **미니어처 섬**과 **제품 연출** 3D 웹 템플릿으로 시작할 수도 있어요.

본인 ChatGPT·Claude에 MCP를 연결한 뒤 **“프롬프트 코치로 이 대화에서 코칭 시작해줘”**라고 요청하고, 같은 AI 대화에서 질문에 답하는 흐름을 안내합니다. 실제 판단과 질문 생성은 연결된 AI가 맡으며 본인 계정의 이용 한도가 적용됩니다. 연결 설정은 처음 한 번이며 질문마다 웹과 AI 사이를 복사할 필요는 없습니다.

**MCP 코치 화면은 호환 확인 중입니다.** 2026-10-15 실제 Claude에서 빈 카드 뒤 화면 표시 오류가 재현되었습니다. ChatGPT 화면은 아직 검증하지 못했습니다. 화면을 시험했다가 보이지 않으면 **“화면이 보이지 않으면 이 대화에서 코칭 시작해줘”**라고 요청해 일반 대화로 이어갑니다. MCP 통신·도구·리소스 응답 성공과 실제 호스트의 화면 표시 성공을 구분합니다. Claude 일반 대화에서는 실제 장면으로 질문 하나·필요한 이유·예시·자유 입력/보류 안내까지 확인했으며, 최종 프롬프트 완성까지의 전체 흐름을 검증한 것은 아닙니다.

이 홈페이지는 연결 안내와 선택적인 장면 정리·보관을 제공합니다. **사이트에서 정리**의 기본 질문은 준비된 안내이며 AI가 문맥을 분석한 결과가 아닙니다. 웹에 이미 작성한 장면을 AI로 가져가는 요청문과, 완성본을 웹에 보관하는 붙여넣기 기능도 남겨 두었습니다. 홈페이지의 직접 AI 대화는 승인 후 연동 준비 중이며 동작하지 않는 로그인 버튼은 제공하지 않습니다. 홈페이지와 AI 대화는 자동 동기화되지 않습니다.

## 왜 이런 구조인가

원하는 결과를 설명할 때는 목적, 대상의 관계, 표현, 제약과 확인 기준이 도움이 됩니다. 필요한 조건을 분명히 적고 실제 결과와 비교하는 과정을 연습하도록 구성했어요. 결과는 모델의 능력과 도구 설정에도 영향을 받으므로, 조건을 많이 적었다는 이유만으로 원하는 결과가 보장되지는 않습니다.

| 구역 | 하는 일 |
|---|---|
| **자유 장면** | 2D Image·3D Web·Video 중 결과물을 고르고 장면을 한 문장으로 시작합니다. 목적 → 대상과 구성 → 표현과 결과물 → 제약과 확인 기준을 필요한 만큼 적습니다. 장면 아이디어 외 항목은 비워 두어도 되고, 빈칸과 설명용 예시는 요청문에 들어가지 않습니다. |
| **작성 가이드** | 조건 토글로 짧은 요청과 구체화한 요청을 비교합니다. 목표와 쓰임, 관찰 가능한 조건, 출력과 우선순위, 참고 자료의 역할, 결과 비교와 반복이라는 다섯 원칙을 설명합니다. 예시를 조작해도 내 작성 내용은 바뀌지 않습니다. |
| **예시 장면 설정** | 기존 3D 웹 템플릿에서는 결정 항목마다 `내가 정함 / AI에게 / 모름`을 고릅니다. 미정 항목은 두 가지 안을 제안하도록 요청문에 들어가고, 선택한 조건에 대응하는 **확인 기준**을 함께 제공합니다. |
| **참고 이미지** | 참고 이미지를 여러 장 올리고, 장마다 구도·대상·표현 등 **참고할 역할**과 메모를 답니다. 프롬프트에 번호와 역할이 적힙니다. |
| **질문으로 구체화** | **내 AI에서 구체화**는 연결된 AI 대화에서 질문받는 방법과 시험 중인 화면의 상태를 안내합니다. 웹의 기존 장면 전달과 완성본 가져오기는 선택 항목입니다. **사이트에서 정리**는 준비된 기본 질문·이유·예시와 답변 저장, 보류, 수정, 중간 마침을 제공합니다. |
| **첫 프롬프트** | 자유 장면은 내가 쓴 표현을 그대로 정리합니다. 확인 목록은 입력 여부만 표시하며 문장의 정확성이나 품질 점수가 아닙니다. 기존 템플릿은 준비된 영문·국문 문장을 선택해 볼 수 있고, 직접 쓴 내용은 번역하지 않습니다. 프롬프트 복사와 TXT 저장을 지원합니다. |
| **수정 코치** | 실제 결과에서 바꿀 위치와 대상, 문제와 원하는 변화를 골라 **수정 요청문**을 만듭니다. 증상별 설명과 일부 템플릿의 전후 예시를 참고할 수 있습니다. 잘 나온 부분은 **유지할 내용**으로 남겨 다음 요청에 포함합니다. |
| **수정 기록** | 수정 요청, 스크린샷, 직접 매긴 별점과 해결 여부를 남깁니다. 기록에서 반복해서 수정한 부분을 살펴봅니다. |
| **보관 · 설정** | 프로젝트 JSON 내보내기와 삭제. 시작 화면에서 JSON을 다시 불러올 수 있습니다. |

영어를 반드시 사용할 필요는 없습니다. 사용하는 모델과 도구가 지원하는 언어·설정을 확인하고, 직접 읽으며 수정할 수 있는 표현으로 요청해 보세요.

## 사용 순서

1. 시작 화면의 **내 AI에 프롬프트 코치 연결하기**에서 본인 ChatGPT·Claude에 MCP를 추가합니다. 서버용 계정이나 API 키는 필요하지 않습니다.
2. AI에게 **“프롬프트 코치로 이 대화에서 코칭 시작해줘”**라고 요청하고 만들 결과물과 장면을 설명합니다.
3. 같은 대화에서 중요한 질문 하나와 그 이유를 읽고 답하거나 보류합니다. 현재 Claude에서는 코치 화면 표시 오류가 확인됐으며 ChatGPT 화면은 미검증입니다. 화면 시험은 선택 사항입니다.
4. 확정한 조건을 확인한 뒤 프롬프트를 완성합니다. 웹으로 가져오지 않아도 AI에서 완성본을 사용할 수 있습니다.

### 웹의 정리·보관 기능을 함께 쓰려면

- **웹에서 장면을 먼저 정리하기**로 프로젝트를 만듭니다. 작성 가이드, 기본 질문과 참고 이미지 정리는 기존처럼 동작합니다.
- **질문으로 구체화 → 내 AI에서 구체화 → 웹에서 이미 작성한 장면 가져가기**는 선택 기능입니다. 요청문은 원문·저장한 답변·보류를 보존하고, 참고 이미지 파일 자체는 포함하지 않습니다. 이미지가 필요하면 AI에 직접 첨부합니다.
- **완성한 프롬프트 가져오기**도 선택 기능입니다. 완성본을 웹에 남기고 싶을 때 붙여 넣고 **이 프롬프트 사용하기**를 누릅니다. 이전에 가져온 초안과 적용한 프롬프트는 유지합니다.
- **사이트에서 정리**는 준비된 기본 질문에 답하거나 보류하는 기능입니다. 작성 중인 문장·예시·보류 항목은 확정 조건에 포함하지 않습니다.
- 실제 결과를 확인하고 **수정 코치**와 **수정 기록**으로 다듬습니다. **보관 · 설정 → 프로젝트 JSON 내보내기**로 이 브라우저의 프로젝트를 백업하고, 시작 화면의 **JSON 열기**로 복원할 수 있습니다.

### 원문과 답변 보존

기본 질문의 답변은 장면 설정 원문을 덮어쓰지 않습니다. 저장한 답변은 원문에서 비어 있는 항목에만 더해 요청문을 구성합니다. 장면·참고 이미지 역할·유지 조건·결과물 종류가 바뀌면 이전 답변은 보관한 채 새 요청에서 제외합니다. 사용자가 현재 장면을 확인하고 이어 쓰기를 선택해야 다시 포함되며, 장면 설정에 이미 입력한 항목은 원문을 우선합니다. 답변을 고칠 때도 저장하기 전까지 이전 확정 답변을 유지합니다.

## AI 사용량과 향후 계정 연결

현재 코칭 대화는 `https://chatgpt.com/` 또는 `https://claude.ai/`에서 사용자가 직접 진행합니다. 해당 계정의 요금제와 사용 한도가 적용되며, 이 사이트는 API 키를 요구하거나 외부 AI 대화를 자동으로 읽지 않습니다. 외부 링크에는 장면 내용이나 인증 정보를 넣지 않습니다. 대화 전체가 자동으로 가져와지는 것은 아니며, 사용자가 붙여 넣은 프롬프트와 메모만 브라우저에 보관합니다.

향후 사이트 안에서 **Sign in with ChatGPT + ChatGPT plan usage**를 제공하려면 공개 웹 서비스에 대한 승인과 등록 정보를 먼저 받아야 합니다. 로그인 권한만으로 사용량 연결이 허용되는 것은 아닙니다. 승인 전 OAuth 로그인이나 운영자 API 비용으로 대신 실행하는 경로는 구현하지 않았습니다. [공식 적용 범위](https://developers.openai.com/siwc/token-sharing-open-source), [웹 로그인 안내](https://developers.openai.com/siwc/website).

### 내 AI에 MCP 연결하기

시작 화면과 **내 AI에서 구체화**에서 Claude 또는 ChatGPT를 선택할 수 있습니다. 서버 주소를 복사해 본인 AI에 사용자 지정 MCP로 추가합니다. 프롬프트 코치 서버는 별도 계정·API 키·인증을 요구하지 않습니다. 계정·조직이 MCP 연결이나 화면을 지원하지 않을 수 있으며, 그런 환경에서는 일반 대화로 코칭할 수 있습니다. Claude Code·Codex용 연결 설정문은 등록 확인·도구 확인을 구분하고 기존 연결을 임의로 덮어쓰지 않습니다.

메뉴 역할은 다음과 같습니다.

| 메뉴 | 역할 |
|---|---|
| **코칭 시작하기 — 장면 입력·질문·답변** (`coach-scene`) | 현재는 일반 AI 대화로 코칭을 시작합니다. 시험 중인 화면은 “프롬프트 코치 화면 열어줘”라고 명시적으로 요청할 때 시도합니다. |
| **사용 방법 보기 — 코치 이용 안내** (`prompt-coach://rules`) | 설명 자료를 읽습니다. 코칭을 시작하는 메뉴가 아닙니다. |

기본 흐름에는 장면·답변을 웹과 AI 사이에서 계속 복사하는 절차가 없습니다. 웹의 선택적 요청문은 이미 보관한 장면을 이어 쓰고 싶을 때 사용하며, 원문과 저장한 답변·보류 내용을 유지합니다. 홈페이지에 저장한 프로젝트는 자동으로 전송·수정되지 않습니다. 화면 지원 여부를 확인하지 않은 채 화면을 열었다고 안내하지 않습니다.

별도 MCP 패키지의 작업 원본은 `/Users/aryeon/Documents/PromptProject/prompt-coach-mcp`에 있고, 버전 관리용 소스는 [integrations/prompt-coach-mcp](integrations/prompt-coach-mcp/README.md)에 보관합니다. 기존 코칭 안내·조건 입력 여부 확인·최신 확정 장면 조립 도구 3개에 코치 화면 열기·답변 전달·코치 결과 표시 도구를 더해 총 6개를 제공합니다. MCP 서버는 별도 AI API를 호출하지 않습니다. 원격 서버는 Cloudflare Workers, 로컬 개발은 stdio 또는 Streamable HTTP를 사용합니다. 소스 보관본에는 의존성 설치 폴더, 생성된 UI, Cloudflare 로그인 정보와 개인 연결 문서를 포함하지 않습니다. [화면·상태·호스트 어댑터 구조](integrations/prompt-coach-mcp/ARCHITECTURE.md)와 패키지 테스트에서 실제 도구 계약을 확인할 수 있습니다.

사이트의 연결 설정은 `public/coach-connection.json`에서 관리합니다. `availability`는 `hosted`(고정 서버), `temporary`(임시 서버), `unavailable`(주소 미제공)이며, `endpoint`는 검증한 실제 HTTPS `/mcp` 주소만 넣습니다. 이 파일은 서비스 워커의 오프라인 캐시에서 제외합니다. 설정 로드는 서버 생존이나 학생 계정 연결 성공을 뜻하지 않습니다. 주소 변경 후 홈페이지를 별도로 배포해야 합니다.

MCP 코치 화면은 AI 서비스 내부의 화면입니다. 외부 홈페이지의 AI 사용 권한을 만들지는 않습니다. 홈페이지 직접 계정 연결이 승인되면 준비된 질문·답변 UI와 코칭 규칙을 활용하되, 승인된 로그인·사용량 연결을 별도로 구현하고 검증해야 합니다. [MCP Apps 구조](https://apps.extensions.modelcontextprotocol.io/api/documents/overview.html).

## 템플릿 갈아 끼우기

템플릿은 `public/templates/*.json` 파일 하나가 만들고 싶은 장면 하나에 대응합니다. 코드를 건드리지 않고 추가할 수 있습니다.

1. `public/templates/<id>.json`을 만듭니다. 구조는 `src/types.ts`의 `Template`을 따르고, `miniature-island.json`이 전체 예, `product-shot.json`이 작은 예입니다.
2. `public/templates/index.json`에 `{ "id", "name", "description", "file" }` 한 줄을 추가합니다.

템플릿 한 개에 들어가는 것:

- `decisions` — 결정 항목. `kind`는 `choice`(하나) / `multi`(여러 개) / `text`(자유 입력). 선택지마다 `text`(영/한 프롬프트 문장)와 선택 시 추가될 `checklist`. `importance: "core"`는 "핵심" 표시, `"nice"`인 자유 입력은 비워 둬도 미결정으로 세지 않습니다.
- `sections` — 프롬프트 순서. 각 섹션은 결정 id 목록이거나 `auto`(참고 이미지 / 미결정 항목 / 검수 기준 / 잠금 / 작업 방식).
- `checklistBase`, `process` — 항상 붙는 검수 기준과 작업 방식.
- `diagnosis` — 진단 목록. 갈래(category) → 증상(symptom). 증상마다 `label`/`labelEn`, `fix`(수정 요청 문장, `{target}` 자리에 사용자가 고른 대상이 들어감), `why`(왜 그런지 설명), `examples`(전후 사진. `public/` 아래 경로와 설명. 미니어처 섬 템플릿의 사진은 `public/examples/miniature-island/`에 있고, 디오라마 아일랜드 프로젝트에서 실제로 찍은 것입니다).
- `compareAxes` — 참고 이미지와 비교하는 축.
- `feelDictionary` — 일반인의 말 → 증상 id → 기술 용어.
- `targets` — "그 자리에 있는 것" 선택지 (`ko`/`en`).

템플릿 파일이 잘못되면(중복 id, 없는 증상을 가리키는 경우 등) 앱 상단에 어디가 틀렸는지 표시됩니다.

## 개발

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # dist/
npm run lint
node --test tests/*.test.ts
```

Vite + React + TypeScript로 만들었습니다. 상태는 IndexedDB(`src/lib/db.ts`), 자유 장면의 원문 정리는 `src/lib/free-prompt.ts`, 코칭 요청과 보관 형식 검증은 `src/lib/coach-handoff.ts`, 템플릿과 수정 요청 조립은 `src/lib/assemble.ts`, 화면은 `src/components/`에 있습니다. 테스트는 TypeScript를 직접 실행할 수 있는 최신 Node.js에서 실행합니다. `main`에 푸시하면 GitHub Actions가 GitHub Pages로 배포합니다(`.github/workflows/pages.yml`, 저장소 설정 → Pages → Source를 "GitHub Actions"로).

## 화면 구성

Studio Penumbra의 다른 Lab과 같은 흑백 명도, IBM Plex 글꼴, 카드·버튼 체계를 사용합니다. 장면 설정은 그룹별로 펼쳐 보고, 수정 코치는 한 단계씩 진행합니다. 같은 프로젝트에서 메뉴를 오가는 동안 작성 중인 수정 요청을 유지합니다. 새로고침하기 전에 완성된 수정 요청은 기록에 저장하세요.

연결 설정문은 실제로 등록·도구 사용 가능 여부를 확인한 뒤 같은 AI 대화에서 코칭하도록 안내합니다. 시험 중인 화면은 사용자가 명시적으로 요청할 때만 `open_prompt_coach`를 시도합니다. 아직 없는 매체나 장면은 임의로 선택하지 않고 사용자에게 묻습니다. 장면과 매체가 이미 있으면 다시 입력하게 하지 않습니다. 사이트의 기존 `#scene` 링크는 프로젝트를 바꾸지 않고 장면 설정을 여는 보조 경로로 유지합니다.
