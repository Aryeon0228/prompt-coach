# 프롬프트 코치

원하는 장면을 구체화하고, 결과를 보며 프롬프트를 다듬는 인터랙티브 도구예요. 코딩 AI에게 줄 **첫 프롬프트**를 만들고, 결과가 어색할 때는 **어디가 · 무엇이 · 어떻게** 이상한지 골라 **수정 프롬프트**로 바꿔 볼 수 있어요. 서버 없이 브라우저에서만 돌아가고(PC와 모바일 모두, 홈 화면에 추가하면 앱처럼 열려요), 내용은 기기에 저장돼요. 프로젝트는 JSON 파일로 내보내 보관하거나 다른 기기에서 이어갈 수 있어요.

## 왜 이런 구조인가

AI가 좋은 결과를 못 내는 이유는 거의 둘 중 하나예요. 하나는 결정을 안 해 줘서 AI가 멋대로 정하는 것, 다른 하나는 틀린 걸 틀렸다고 말해 주지 못하는 것. 이 도구는 그 둘을 각각 맡는 두 부분으로 나뉘고, 둘 다 같은 결정 목록을 공유해요.

| 구역 | 하는 일 |
|---|---|
| **결정** | 템플릿의 결정 항목마다 `내가 정함 / AI에게 / 모름`을 고릅니다. 아직 정하지 않은 항목이 눈에 보이고, 모른다고 둔 항목은 프롬프트에 "두 가지 안을 내고 물어봐 줘"로 들어갑니다. 선택마다 **검수 기준**이 자동으로 붙습니다. |
| **참고** | 참고 이미지를 여러 장 올리고, 장마다 **역할**(구도 / 그림체 / 특정 오브젝트 / 색감 / 하지 말 것)과 메모를 답니다. 프롬프트에 번호와 역할이 적힙니다. |
| **첫 프롬프트** | 영어(AI에 붙여넣기)와 한국어(뜻 확인용)를 나란히 보여 주고, 복사와 TXT 저장이 됩니다. 결과를 보고 마음에 드는 것을 **잠금**에 적어 두면 이후 모든 프롬프트에 "바꾸지 마"로 붙습니다. |
| **코치** | 결과 스크린샷에 영역 표시 → 거기 있는 것 → 문제 갈래(형태 / 색 / 빛 / 재질 / 배치 / 움직임 / 구도 / 성능) → 구체적인 증상 → 참고와 가장 다른 점 → **수정 프롬프트**. 증상마다 "왜 이렇게 되는 걸까요?" 설명과 **전후 사진**이 붙어서 그 자리에서 배웁니다. "플라스틱 같아요" 같은 말로 찾는 **느낌 사전**도 있습니다. |
| **기록** | 수정 요청마다 프롬프트, 스크린샷, 별점, 해결 여부를 남깁니다. 쌓이면 자주 틀리는 패턴을 보여 줍니다. |
| **설정** | 프로젝트 JSON 내보내기와 삭제. 시작 화면에서 JSON을 다시 불러올 수 있습니다. |

## 템플릿 갈아 끼우기

템플릿은 `public/templates/*.json` 파일 하나가 만들고 싶은 장면 하나에 대응합니다. 코드를 건드리지 않고 추가할 수 있습니다.

1. `public/templates/<id>.json`을 만듭니다. 구조는 `src/types.ts`의 `Template`을 따르고, `miniature-island.json`이 전체 예, `product-shot.json`이 작은 예입니다.
2. `public/templates/index.json`에 `{ "id", "name", "description", "file" }` 한 줄을 추가합니다.

템플릿 한 개에 들어가는 것:

- `decisions` — 결정 항목. `kind`는 `choice`(하나) / `multi`(여러 개) / `text`(자유 입력). 선택지마다 `text`(영/한 프롬프트 문장)와 선택 시 추가될 `checklist`. `importance: "core"`는 "핵심" 표시, `"nice"`인 자유 입력은 비워 둬도 미결정으로 세지 않습니다.
- `sections` — 프롬프트 순서. 각 섹션은 결정 id 목록이거나 `auto`(참고 이미지 / 미결정 항목 / 검수 기준 / 잠금 / 작업 방식).
- `checklistBase`, `process` — 항상 붙는 검수 기준과 작업 방식.
- `diagnosis` — 진단 목록. 갈래(category) → 증상(symptom). 증상마다 `label`/`labelEn`, `fix`(수정 요청 문장, `{target}` 자리에 사용자가 고른 대상이 들어감), `why`(왜 그런지 설명), `examples`(전후 사진. `public/` 아래 경로와 설명. 미니어처 섬 템플릿의 사진은 `public/examples/miniature-island/`에 있고, 디오라마 아일랜드 프로젝트에서 실제로 찍은 것입니다).
- `compareAxes` — 참고 이미지와 비교하는 축.
- `feelDictionary` — 일반인의 말 → 증상 id → 기술 용어.
- `targets` — "그 자리에 있는 것" 선택지 (`ko`/`en`).

템플릿 파일이 잘못되면(중복 id, 없는 증상을 가리키는 경우 등) 앱 상단에 어디가 틀렸는지 표시됩니다.

## 개발

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # dist/
```

Vite + React + TypeScript이고, 의존성은 React와 PWA 플러그인뿐입니다. 상태는 IndexedDB(`src/lib/db.ts`), 프롬프트 조립은 `src/lib/assemble.ts`, 화면은 `src/components/`에 있습니다. `main`에 푸시하면 GitHub Actions가 GitHub Pages로 배포합니다(`.github/workflows/pages.yml`, 저장소 설정 → Pages → Source를 "GitHub Actions"로).

## 사용 순서

1. 템플릿을 고르고 결정을 내린다 → 참고 이미지를 단다 → 첫 프롬프트를 복사해 코딩 AI에 붙여넣고, 이미지를 같은 순서로 첨부한다.
2. 결과가 나오면 마음에 드는 것부터 **잠금**에 적는다.
3. 어색한 곳마다 **코치**에서 한 번에 하나씩 수정 프롬프트를 만든다 → 결과가 나오면 별점을 남긴다.
4. 작업을 보관하거나 옮길 때는 **설정 → 프로젝트 JSON 내보내기**로 저장한다. 기록 탭에서 반복해서 수정한 부분을 살펴보며 다음 프롬프트를 다듬을 수 있습니다.
