# Prompt Coach: 화면과 AI 호스트의 경계

## 구현된 흐름과 확인 범위

현재 권장 사용 흐름은 연결된 AI의 일반 대화에서 장면을 설명하고 질문에 답하는 것입니다. 화면 구현은 장면 입력 → 질문·답변 → 검토·확정 순서이며 MCP Apps를 지원하는 호스트를 대상으로 합니다. **2026-10-15 Claude에서는 실제 화면 표시 오류가 재현되었고 ChatGPT 화면은 미검증입니다.** 아래 구조는 구현과 로컬 테스트의 설명이며 실제 호스트에서 전체 화면 흐름이 성공했다는 뜻이 아닙니다.

Claude의 일반 대화에서 ‘유리구 안 작은 도서관, 3D 웹’을 입력한 뒤 코칭 안내 도구 호출, 시점 질문 하나, 필요한 이유, 예시 3개, 자유 입력·보류 안내까지 확인했습니다. 최종 프롬프트 완성까지의 전체 대화는 검증하지 않았습니다.

서버는 입력을 검증하고 다음 상태를 반환합니다. 문맥을 이해해 질문과 이유를 만드는 주체는 현재 대화 중인 AI입니다. 서버가 별도 OpenAI·Anthropic API를 호출하거나 이용자의 계정 토큰을 발급받는 구조가 아닙니다.

```text
AI 호스트 ── open_prompt_coach ──▶ MCP 서버 ──▶ 코치 화면 리소스
                                     ▲
화면의 사용자 동작 ── submit ──────────┘
      │                       다음 상태 + hostRequest
      └── 호스트 대화에 명시적 요청 ──▶ 현재 AI
                                      │
                                show_prompt_coach
                                      │
                                다음 질문/검토 화면
```

사용자가 최종 확인을 누르면 서버는 완성 상태를 반환합니다. 확인 동작에는 모델 호출이 필요하지 않습니다. 새 장면은 별도 카드에서 시작하고 기존 카드의 원문과 기록은 그대로 남깁니다.

## 파일별 책임

| 구성 | 책임 |
| --- | --- |
| `ui/view.mjs`, `ui/styles.css` | 장면·질문·검토·완성 화면. 사용자와 AI 문자열은 DOM 텍스트로 표시 |
| `ui/model.mjs` | 화면 상태, 입력 초안, 검증, 제출, 명시적 재전송, 내보내기 |
| `ui/host-adapter.mjs` | MCP Apps 연결, 도구 호출, 호스트 메시지, 지원되는 저장/다운로드 |
| `ui/app.js` | 모델·뷰·호스트 어댑터 조립 |
| `coach-session.mjs` | 순수 상태 전이와 입력 검증, 상태 스냅샷 직렬화, AI 요청 생성 |
| `coaching.mjs` | 2D Image·3D Web·Video 코칭 관점과 일반 대화용 규칙 |
| `mcp-core.mjs` | 공통 MCP 도구·프롬프트·리소스 등록과 노출 범위 |
| `worker.mjs`, `server.mjs` | Workers HTTP 또는 로컬 HTTP/stdio 전송 |
| `scripts/build-ui.mjs` | 스크립트·스타일을 외부 자산 없이 HTML로 묶어 `generated/` 생성 |
| `scripts/preview-*` | 실제 AI를 호출하지 않는 로컬 호스트 연동 시험 |

화면 HTML 내용의 SHA-256 해시를 리소스 URI에 넣어, UI가 바뀔 때 호스트가 새 리소스를 읽도록 합니다. 리소스 목록에는 현재 주소만 표시합니다. 이전 고정 주소 `ui://prompt-coach/coach-v1.html`과 소문자 16자리 hex로 된 이전 해시 주소는 현재 HTML을 반환하는 호환 템플릿으로 유지합니다. 추가 경로·쿼리·인코딩 변형과 다른 호스트 주소는 허용하지 않습니다. 빌드 결과의 스크립트는 module로 실행합니다.

## 상태·원문 보존

- 서버에 공유 세션 저장소가 없습니다. `state`는 세션 ID·리비전·원문·답변을 포함한 이동 가능한 스냅샷입니다. 서명된 인증정보가 아니며 비밀로 취급하거나 권한 확인에 사용하지 않습니다.
- 상태는 엄격한 스키마와 정규 인코딩을 검사합니다. `pc1.` 스냅샷의 UTF-8 원본은 최대 32 KiB이며 HTTP 요청 본문은 최대 96 KiB입니다. 길이를 넘으면 내용을 자르지 않고 오류를 반환합니다.
- 사용자의 원래 장면, 실제 보낸 답변, 보류한 질문을 보존합니다. AI 질문의 선택적 예시는 사용자가 답변으로 보내기 전까지 확정 조건이 아닙니다.
- 화면이 열린 현재 카드에서는 단계별 입력 초안을 유지합니다. 보내지 않은 답변이 있을 때 ‘여기까지 정리’는 확인을 요청합니다. 검토본을 직접 고치고 AI 수정을 요청하면 편집한 프롬프트를 함께 전달합니다. 초안이 이후 AI 응답으로 만들어진 다른 카드까지 자동 이동하거나 새로고침 뒤 항상 복구되는 것은 아닙니다.
- 화면은 제출 전 전체 기록의 UTF-8 크기와 JSON 부가 크기를 검사합니다. 개별 입력의 글자 수 이내여도 전체 32 KiB 한도를 넘으면 제출하지 않으며, 현재 열린 카드의 원문을 잘라내지 않습니다.
- 전송 실패 후 재시도는 이미 처리한 답변 제출을 반복하지 않고 AI 호스트로의 요청만 다시 보냅니다. 자동 재시도나 자동 AI 호출은 없습니다.
- 상태와 초안은 현재 카드의 세션에 묶입니다. 위젯 상태 저장·다운로드 지원은 호스트에 따라 다릅니다. 모든 호스트나 새로고침에서 영구 복구를 보장하지 않으므로 완성본은 사용자가 직접 저장합니다.

## 공개 범위와 개인정보

`open_prompt_coach`는 모델·앱에서, `submit_prompt_coach_input`은 앱에서, `show_prompt_coach`는 모델에서 사용하도록 메타데이터를 제공합니다. 호스트가 해당 노출 규칙과 MCP Apps 기능을 지원해야 합니다.

서버 도구는 외부 네트워크 AI 호출이나 대화 저장을 수행하지 않습니다. 다만 요청에 담긴 장면·답변은 MCP 서버와 Cloudflare를 거쳐 처리되고 호스트 도구 결과·대화 문맥에 포함됩니다. ‘서버에 저장하지 않음’은 ‘서버에 보내지 않음’을 뜻하지 않습니다. 사용자의 AI 계정 한도와 서버 운영 비용은 구분합니다.

웹사이트 저장 내용은 MCP 연결만으로 자동 읽기·쓰기·동기화되지 않습니다. 웹에서 작성한 내용의 가져가기와 완성본 가져오기는 사용자가 선택해 실행합니다.

## 호스트 기능 지원과 오류

코치 화면은 표준 MCP Apps 연결을 사용합니다. Claude에서 전체 앱, 공식 브라우저 번들, 최소 연결 화면을 시험했으나 모두 표시 오류가 재현되었습니다. 실제 UI 리소스 읽기 요청은 정상 응답했으므로 리소스 응답 성공만으로 호스트의 렌더링 성공이나 실패 원인을 확정하지 않습니다.

도구 호출이 성공한 것만으로 화면 표시나 AI의 응답 생성을 확정하지 않습니다. 화면 또는 메시지 전달을 지원하지 않는 환경에서는 그 제한을 알리고 일반 AI 대화로 이어갑니다. 호스트가 메시지를 거부하면 현재 열린 카드에서 입력과 재전송할 요청을 유지합니다. 사용자가 화면 시험을 명시적으로 원할 때만 화면 열기를 시도하며, 실패하면 반복해서 열지 않고 일반 대화로 이어갑니다.

로컬 미리보기는 고정 질문으로 UI·전송 계약을 검사합니다. 이것은 실제 ChatGPT·Claude 계정에서의 E2E 검증을 대신하지 않습니다. 공식 호스트에서 도구 목록, 렌더링, 사용자 허용, 질문 수신, 답변 전송, 검토·확정을 별도로 확인해야 합니다.

## 홈페이지 직접 AI 연결을 위한 재사용

현재 외부 홈페이지의 직접 AI 대화는 승인·연동 준비 단계입니다. MCP 연결은 외부 사이트에 사용자의 ChatGPT·Claude 추론을 직접 호출할 권한을 주지 않습니다. 승인만으로 기능이 열리는 것도 아닙니다.

승인 후 허용된 인증·요금·호출 방식이 확정되면 `ui/host-adapter.mjs`와 같은 인터페이스의 웹용 어댑터를 별도로 구현할 수 있습니다. `ui/model.mjs`, `ui/view.mjs`, 스타일, 코칭 규칙과 검증 원칙은 재사용 가능한 출발점입니다. 인증 콜백·세션·통신 실패·새로고침·계정 전환은 새 통합에서 별도로 설계하고 검증해야 합니다.

현재 React 홈페이지에 그대로 자동 통합된 상태는 아닙니다. 웹 프로젝트 저장 형식과의 연결 역시 별도 작업이며, 기존 데이터를 덮어쓰지 않는 명시적 가져오기·보관 정책이 필요합니다. 작동하지 않는 로그인이나 자동 동기화를 표시하지 않습니다.
